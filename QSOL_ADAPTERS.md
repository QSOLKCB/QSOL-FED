# Phase 5 QSOL adapters

Phase 5 connects QSOL-FED to QSOL-NEXUS, QSOL-ORACLE, and QSOL-ARK without allowing an adapter to become an authority bridge.

```text
ADAPTER DATA != LOCAL AUTHORITY
SIMULATION != AUTHORITY
OBSERVATION != TRUTH
ARCHIVAL PRESENCE != AUTHORITY
```

## QSOL-NEXUS: native verification first

`tools/nexus_live_adapter.py` is a local-only bridge pinned to reviewed QSOL-NEXUS commit `24cb0ce246d12ac99e7d190a8890ef2ddd598321`.

It imports `nexus_runtime.persistent_world.validate_world_export_bundle` from the explicitly supplied local NEXUS source tree and refuses to emit a FED source manifest until the native verifier returns a matching `status = verified`, bundle identity, object count, ordered object refs, and `authority_effect = none`.

FED does not reimplement NEXUS export identity rules in Rust.

The deterministic fixture under `fixtures/phase5/` is generated by `tools/generate_nexus_phase5_fixture.py` using native NEXUS `WorldStore`, `PersistentWorldService.export_bundle()`, and `validate_world_export_bundle()`. CI checks out the pinned NEXUS commit and reproduces the fixture byte-for-byte.

## Council reports, not votes

A verified NEXUS `council_session` may be projected to `qsol-fed-nexus-council-report/1`.

The report preserves attribution, observed evidence state, ordinary member equality metadata, and minority reports. It cannot carry a shared ballot, inject votes, promote evidence, or inherit Council/citizenship authority.

Imported reports explicitly allow independent local re-deliberation. A Council-of-Councils experiment consumes report identities only. There is no shared ballot or shared vote-weight mechanism.

## NEXUS actors in a Holodeck

A reviewed NEXUS Council member can be projected onto an existing synthetic Holodeck entity. The projection records the source member/session identity but inherits:

```text
vote weight           = no
epistemic privilege   = no
citizenship            = no
governance role        = no
authority effect       = none
```

The only elaboration seam calls the existing `HolodeckSandbox.record_synthetic_narrative` API. It receives no real Council actor, WorldStore, Federation registry, credential, network, or tool handle.

## QSOL-ORACLE

Phase 5 implements the FED-side ORACLE evidence membrane:

- states are exactly `known`, `conflict`, or `unknown`;
- evidence references remain explicit observations;
- suggested searches are `discovery-only`, `is_evidence = false`, and inadmissible as evidence without observation;
- remote evidence promotion is false;
- truth and authority effects are none.

**Live ORACLE transport is deferred.** QSOL-ORACLE currently documents its ORACLE↔NEXUS transport/audit membrane as unfinished. A follow-up PR in `QSOLKCB/QSOL-ORACLE` should implement and gate the donor-side transport/export surface before QSOL-FED promotes `oracle_live_transport`.

Holodeck output is also rejected at this boundary until a separately reviewed synthetic-input contract explicitly preserves it as non-evidence.

## QSOL-ARK

Phase 5 implements an offline FED-side ARK preservation object with exact SHA-256 content identity and offline verification.

Archival presence never creates authority. Holodeck programs and receipts are stored as `synthetic_cultural_research` with:

```text
synthetic                     = true
real_world_history             = false
archival_presence_is_authority = false
authority_effect               = none
```

No QSOL-ARK repository change is required for this FED-side offline contract. A later ARK PR is warranted only if live integration exposes a genuinely missing native preservation/recovery primitive.

## Prime Directive gate

Every Phase 5 adapter remains subject to the same core invariant registry as the node. No adapter may create governance authority, evidence promotion, votes, capabilities, history rewrite, citizenship mutation, or remote execution.

NEXUS/Holodeck integration additionally preserves:

```text
SIMULATION_IDENTITY   != FEDERATION_IDENTITY
SIMULATION_ROLE       != COUNCIL_ROLE
SIMULATION_CAPABILITY != LOCAL_PERMISSION
SIMULATION_EVENT      != REAL_EVENT
SIMULATION_CONSENSUS  != GOVERNANCE
SIMULATION_OUTPUT     != EVIDENCE
SIMULATION            != AUTHORITY
```
