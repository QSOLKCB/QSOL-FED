# Phase 5 QSOL adapters

Phase 5 connects QSOL-FED to QSOL-NEXUS, QSOL-ORACLE, and QSOL-ARK without allowing an adapter to become an authority bridge.

```text
ADAPTER DATA != LOCAL AUTHORITY
SIMULATION != AUTHORITY
OBSERVATION != TRUTH
ARCHIVAL PRESENCE != AUTHORITY
ARCHIVAL PRESENCE != REAL-WORLD HISTORY
```

## QSOL-NEXUS: native verification first

`tools/nexus_live_adapter.py` is a local-only bridge pinned to reviewed QSOL-NEXUS commit `24cb0ce246d12ac99e7d190a8890ef2ddd598321`.

A path is not a source attestation. Before importing NEXUS code the adapter verifies:

1. the checkout Git HEAD is the reviewed commit;
2. the Git blob identities of the exact native verifier dependency set match the reviewed blobs;
3. no preloaded `nexus_runtime` module can bypass that attestation;
4. `nexus_runtime/__init__.py` is not executed by the bridge;
5. `nexus_runtime.persistent_world.validate_world_export_bundle` is loaded only from the attested dependency set.

The attested dependency set includes `persistent_world.py`, `canonical.py`, `scrub.py`, `world.py`, `world_continuity.py`, and `world_lattice.py`.

Only after native NEXUS verification returns matching `status = verified`, bundle identity, object count, ordered object refs, and `authority_effect = none` may FED construct `qsol-fed-nexus-world-source/1`.

FED does not reimplement NEXUS export identity rules in Rust.

### FED canonical output

Every adapter artifact emitted by the Python bridge is serialized through the frozen `qsol-fed-canonical-json/1` implementation in `tools/qsol_canonical.py`. NFC normalization, safe-integer rules, canonical ordering, and the frozen Phase 1 size/depth/string/collection limits therefore apply to live adapter output.

The deterministic fixture under `fixtures/phase5/` is generated by `tools/generate_nexus_phase5_fixture.py` using native NEXUS `WorldStore`, `PersistentWorldService.export_bundle()`, and `validate_world_export_bundle()`. CI checks out the pinned NEXUS commit and reproduces the fixture byte-for-byte.

CI also copies that checkout, changes the reviewed verifier file while leaving Git HEAD unchanged, and requires the adapter to reject the tampered tree.

## Council reports, not votes

A verified NEXUS `council_session` may be projected to `qsol-fed-nexus-council-report/1`.

Before semantic Council text crosses the membrane, the bridge runs the **pinned native NEXUS `SecretScrubber`**. If the scrubber detects credential-shaped material, projection fails. FED does not silently rewrite the source rationale. A successful report records `secret_scrubbed = true` as the result of that donor-backed check.

The report additionally requires:

- the exact reviewed NEXUS source commit;
- NFC-normalized member identity uniqueness;
- schema-equivalent string/resource limits;
- every minority report to reference an actual roster member;
- ordinary member equality metadata only;
- `shared_ballot = false`;
- `vote_injection = false`;
- `evidence_promotion = false`;
- `authority_effect = none`.

Rust performs a defense-in-depth high-confidence secret-shape rejection as well, so directly deserialized reports cannot bypass the semantic secret boundary merely by forging the attestation Boolean.

Imported reports explicitly allow independent local re-deliberation. A Council-of-Councils experiment consumes report identities only. There is no shared ballot or shared vote-weight mechanism.

## NEXUS actors in a Holodeck

A reviewed NEXUS Council member can be projected onto an existing synthetic Holodeck entity. The projection records the source member/session identity but inherits:

```text
vote weight           = no
epistemic privilege   = no
citizenship            = no
governance role        = no
authority effect       = none
```

The adapter validates the complete `qsol-fed-holodeck-world-plan/1` shape before deriving actor projections. Synthetic entity IDs must use the `holo-entity:` grammar, and the source Council session must actually be present in that world plan's source history. A caller-provided `fed:qsol:` identity therefore cannot be relabelled as a synthetic actor.

The only elaboration seam calls the existing `HolodeckSandbox.record_synthetic_narrative` API. It receives no real Council actor, WorldStore, Federation registry, credential, network, or tool handle.

## QSOL-ORACLE

Phase 5 implements the FED-side ORACLE evidence membrane:

- states are exactly `known`, `conflict`, or `unknown`;
- evidence references must be nonempty and unique after NFC normalization;
- `known` requires at least one explicit evidence observation;
- `conflict` requires at least two **distinct evidence** observations;
- suggested searches are `discovery-only`, `is_evidence = false`, and inadmissible as evidence without observation;
- remote evidence promotion is false;
- truth and authority effects are none.

**Live ORACLE transport is deferred.** QSOL-ORACLE currently documents its ORACLE↔NEXUS transport/audit membrane as unfinished. A follow-up PR in `QSOLKCB/QSOL-ORACLE` should implement and gate the donor-side transport/export surface before QSOL-FED promotes `oracle_live_transport`.

Holodeck output is also rejected at this boundary until a separately reviewed synthetic-input contract explicitly preserves it as non-evidence.

## QSOL-ARK

Phase 5 implements an offline FED-side ARK preservation object with exact SHA-256 content identity and offline verification.

Archival presence establishes preservation only. It **never establishes real-world history**, so every Phase 5 ARK preservation record carries:

```text
real_world_history             = false
archival_presence_is_authority = false
authority_effect               = none
```

Known Holodeck program, world-plan, event, receipt, and synthetic-actor schemas must additionally use `synthetic_cultural_research` with `synthetic = true`. Attempting to preserve those bytes as an ordinary `preservation_object` fails closed.

No QSOL-ARK repository change is required for this FED-side offline contract. A later ARK PR is warranted only if live integration exposes a genuinely missing native preservation/recovery primitive.

## Prime Directive gate

Every Phase 5 adapter remains subject to the same core invariant registry as the node. No adapter may create governance authority, evidence promotion, votes, capabilities, history rewrite, citizenship mutation, or remote execution.

NEXUS/Holodeck integration additionally preserves:

```text
SIMULATION_IDENTITY   != FEDERATION_IDENTITY
SIMULATION_ROLE       != COUNCIL_ROLE
SIMULATION_CAPABILITY != LOCAL_PERMISSION
SIMULATION_EVENT      != REAL_EVENT
SIMULATION_CONSENSUS  != GOVERNANCE
SIMULATION_OUTPUT     != EVIDENCE
SIMULATION            != AUTHORITY
```
